# Telegram-бот: ИИ-ассистент с пробными запросами и подпиской

Стек: **Python 3.11+ · aiogram 3 · Groq API (OpenAI-совместимый) · SQLite**

## Что умеет
- Отвечает на любые сообщения через ИИ (Groq, модель Llama 3.3 70B по умолчанию)
- 5 бесплатных запросов в день на пользователя (настраивается)
- Подписка за Telegram Stars → безлимит на 30 дней
- Хранит пользователей, лимиты и платежи в SQLite (`bot.db`, создаётся автоматически)
- **Напоминание об окончании подписки** — бот сам пишет пользователю за день (настраивается) до истечения
- **Режимы ответа для подписчиков** (`/mode`) — Обычный, Копирайтер, Кодер, Простыми словами
- **Длинная память диалога у подписчиков** — 30 последних сообщений вместо 6 у бесплатных пользователей
- **Реферальная программа** (`/invite`) — за каждого приглашённого друга оба получают бонусные запросы
- Команды: `/start`, `/help`, `/status`, `/buy`, `/invite`, `/mode`

## 1. Установка

```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Настройка

1. Скопируйте `.env.example` → `.env`
2. Получите **BOT_TOKEN**: напишите [@BotFather](https://t.me/BotFather) → `/newbot`
3. Получите **GROQ_API_KEY**: зарегистрируйтесь на https://console.groq.com/keys (бесплатно)
4. Заполните `.env`:

```
BOT_TOKEN=123456:AAA...
GROQ_API_KEY=gsk_...
```

## 3. Запуск

```bash
python bot.py
```

Бот запустится в режиме polling — этого достаточно для старта и первых пользователей.

## 4. Приём оплаты (Telegram Stars)

Оплата уже подключена через **Telegram Stars** — это самый простой способ:
- Не нужен эквайринг, ИП или юрлицо
- Работает "из коробки" в любом Telegram-боте
- Комиссию и вывод звёзд в деньги настраиваете позже через @BotFather → Stars → Withdraw

Если вместо Stars нужна оплата картой (ЮKassa/Тинькофф), это отдельная интеграция —
скажите, и я добавлю альтернативный обработчик `/buy` с провайдер-токеном ЮKassa.

## 5. Настройка новых функций (необязательно)

В `.env` можно добавить (все значения не обязательны, есть умолчания):

```
# Сколько сообщений помнит бот в диалоге
SHORT_HISTORY_MESSAGES=6      # бесплатные пользователи
LONG_HISTORY_MESSAGES=30      # подписчики

# Реферальная программа
REFERRAL_BONUS_REQUESTS=5     # сколько запросов получают оба за приглашение

# Напоминание об окончании подписки
REMINDER_DAYS_BEFORE=1               # за сколько дней напомнить
REMINDER_CHECK_INTERVAL_HOURS=6      # как часто бот проверяет, кому напомнить
```

Режимы ответа (`/mode`) сейчас заданы в коде в `config.py` (словарь `MODES`) — можно менять тексты промптов или добавлять новые режимы прямо там.

## 7. Как это работает

- Каждый пользователь получает запись в SQLite при первом сообщении
- Счётчик `requests_today` сбрасывается автоматически при смене даты
- Если у пользователя активна подписка (`subscription_until` в будущем) — лимит не проверяется
- При успешной оплате `subscription_until` продлевается на `SUBSCRIPTION_DAYS` (если подписка уже была активна — от даты её окончания, а не от текущего момента)
- История диалога хранится в памяти (по 6 последних сообщений на пользователя) — простое решение для старта; при перезапуске бота сбрасывается

## 8. Что стоит сделать перед реальным запуском

- [ ] Задеплоить на сервер/VPS с автоперезапуском (systemd, Docker или pm2-аналог)
- [ ] Перейти с SQLite на PostgreSQL при росте базы пользователей
- [ ] Добавить обработку ошибок Groq API (rate limit, недоступность) — сейчас есть базовый try/except
- [ ] Настроить логирование в файл, не только в консоль
- [ ] Продумать текст политики использования/оферты (обязательно для приёма платежей)
- [ ] При росте нагрузки — перейти с polling на webhook

## 9. Масштабирование модели (когда появятся первые подписчики)

Бесплатный тариф Groq ограничен ~1000 запросов/день на аккаунт — этого хватает
примерно на 30–50 активных пользователей в день. Как только появятся первые
платящие подписчики, можно подключить платный тариф Groq (около $0.05–0.10
за 1M токенов) — маржа остаётся очень высокой, а переход требует только
смены ключа API в `.env`, код менять не нужно.

## 10. Новые функции монетизации и вовлечения

### FOMO и прогресс-бар
После каждого ответа бесплатному пользователю бот показывает короткий teaser о том, что в подписке
ответ был бы полнее, и прогресс-бар использованных запросов за день. Когда лимит исчерпан — показывает
обратный отсчёт до сброса (полночь по времени сервера).

### Золотой запрос
Раз в `GOLDEN_QUERY_INTERVAL_DAYS` дней (по умолчанию 7) бесплатный пользователь может нажать кнопку
🌟 «Золотой запрос» и получить один ответ на правах подписчика (длинная память, режимы). После этого
бот предлагает оформить подписку.

### Динамическая скидка
Если бесплатный пользователь активен `DYNAMIC_DISCOUNT_ACTIVE_DAYS` дней подряд (по умолчанию 3) и ещё
не покупал подписку, бот один раз предлагает временную скидку (`DYNAMIC_DISCOUNT_PERCENT`, по умолчанию
50%) на `DYNAMIC_DISCOUNT_WINDOW_HOURS` часов. Скидка автоматически подставляется в счёт на оплату.

### Стрик и геймификация
Каждые `STREAK_BONUS_EVERY_DAYS` дней подряд активности (по умолчанию 7) пользователь получает
`STREAK_BONUS_REQUESTS` бонусных запроса. При достижении такого стрика также появляется дополнительная
скидка `STREAK_DISCOUNT_PERCENT`% при покупке подписки (берётся большая из скидок — динамической или
за стрик, суммарно не выше 70%).

### Ограничение контекста у бесплатных пользователей
Если бесплатный пользователь не писал боту дольше `FREE_CONTEXT_TTL_MINUTES` минут (по умолчанию 15),
память диалога сбрасывается — это отличает бесплатный тариф от подписки, где память сохраняется дольше
и по количеству сообщений (`LONG_HISTORY_MESSAGES`).

### Загрузка PDF (только подписка)
Подписчик может отправить боту PDF-файл (с подписью-вопросом или без — тогда бот сделает краткий
пересказ). Текст извлекается через `pypdf`, обрезается до ~8000 символов и передаётся модели.

### Генерация изображений (только подписка)
Команда `/image <описание>` генерирует картинку через бесплатный публичный сервис
[Pollinations.ai](https://pollinations.ai) — API-ключ не нужен. Это публичный сторонний сервис без
SLA: при необходимости стабильного качества и приватности стоит заменить на платный провайдер
(например, OpenAI Images или Stability AI) — потребуется дополнительный API-ключ.

### Реферальная программа (усиленная)
- Приглашение друга: оба получают `REFERRAL_BONUS_REQUESTS` запросов (как раньше).
- Если приглашённый друг **купит подписку** — пригласивший дополнительно получает
  `REFERRAL_SUBSCRIPTION_BONUS_REQUESTS` бонусных запросов (по умолчанию 50).
- `/leaderboard` — топ-10 пользователей по числу приглашённых друзей.
- `/reward_top10` — команда только для администратора: вручную награждает топ-10 бесплатным месяцем
  подписки. Периодичность конкурса (еженедельно/ежемесячно) в задаче не была уточнена, поэтому
  награждение запускается вручную, а не по автоматическому расписанию — при необходимости можно
  повесить эту же команду на cron/планировщик.

### Важные допущения, которые пришлось сделать
- Пункт «премиум-модель с другим системным промптом» уже реализован через существующую систему
  режимов (`/mode`) — отдельную вторую модель не добавлял, так как явного требования и дополнительного
  API-ключа под неё не было.
- Реферальный бонус за покупку друга начисляется как **бонусные запросы** (не скидка) — в задаче было
  «или», выбрал более простой и однозначный вариант. Поменять на скидку можно, сказать — доработаю.

## 11. RAG, веб-поиск, мультимодальность, анти-спам, fallback

### 📚 База знаний (RAG) — только подписка, режим «База знаний»
Администратор (`ADMIN_USERNAMES`) загружает документы командой `/kb_add` (бот попросит прислать
PDF). Текст автоматически режется на куски (`RAG_CHUNK_SIZE`, по умолчанию 800 символов) и
сохраняется в SQLite. Подписчик включает режим `📚 База знаний` через `/mode` — после этого бот
ищет релевантные куски по ключевым словам (упрощённый TF‑IDF, без внешнего embeddings API — работает
локально и бесплатно) и отвечает **строго на их основе**. Если релевантных фрагментов не нашлось,
бот честно говорит, что этой информации в базе нет, вместо того чтобы придумывать ответ.
- `/kb_list` — список загруженных документов (админ)
- `/kb_clear` — очистить базу знаний (админ)
- Это упрощённая реализация без векторного поиска — для больших баз (тысячи страниц) точность
  поиска по ключевым словам будет ниже, чем у полноценного RAG с embeddings; для FAQ и небольших
  инструкций (до ~1000 кусков) работает вполне надёжно.

### 🌐 Веб-поиск в реальном времени — только подписка
Кнопка `🌐 Веб-поиск` или команда `/search <запрос>`. Использует **встроенный** в Groq инструмент
веб-поиска (модель `groq/compound-mini`) — отдельный API-ключ для поиска не нужен, тот же ключ Groq.
Подходит для новостей, курсов валют, погоды и любых вопросов, требующих актуальных данных.

### 🎙 Голосовые сообщения — только подписка
Присланное голосовое сообщение распознаётся через Groq Whisper (`whisper-large-v3-turbo`),
показывается распознанный текст, и дальше ответ формируется как на обычный текстовый вопрос
(с той же памятью диалога, режимами и т.д.). Ограничение по длительности — `VOICE_MAX_DURATION_SECONDS`
(по умолчанию 120 сек).

### 📷 Анализ изображений — только подписка
Просто отправь фото (можно с подписью-вопросом) — бот проанализирует его через мультимодальную
модель Groq (`qwen/qwen3.6-27b`). Без подписи бот сам опишет, что на фото.

### 🛡 Rate limiting и анти-спам — действует на всех пользователей
- Минимальная пауза между запросами (`TEXT_COOLDOWN_SECONDS`, 2 сек) — защита от случайных дублей.
- Если пользователь шлёт больше `SPAM_MAX_MESSAGES` сообщений за `SPAM_WINDOW_SECONDS` секунд —
  временная блокировка на `SPAM_BLOCK_SECONDS` секунд с предупреждением.
- Администратор не ограничивается ни одним из этих правил.
- Отдельные, более мягкие лимиты — на генерацию картинок (`IMAGE_COOLDOWN_SECONDS`, 16 сек) и
  веб-поиск (`SEARCH_COOLDOWN_SECONDS`, 10 сек), так как это более тяжёлые операции.

### 🙈 Fallback с извинениями
Вместо технических сообщений об ошибках (таймауты, сбои API, проблемы с загрузкой файлов) бот
показывает одну из дружелюбных фраз-извинений (`FALLBACK_APOLOGIES` в `config.py`) и предлагает
попробовать ещё раз. Технические детали ошибки при этом всё равно попадают в лог (`logging.error`)
для отладки — пользователь их не видит.

### Обновлённая структура доступа (что бесплатно, что по подписке)

🆓 **Бесплатно:**
- 5 текстовых запросов в день (+ бонусные за рефералов и стрик)
- Короткая память диалога в рамках сессии (сбрасывается через `FREE_CONTEXT_TTL_MINUTES`)
- Золотой запрос раз в неделю — full доступ на одно сообщение
- Реферальная программа, лидерборд, статус, скидки за активность

💎 **По подписке:**
- Безлимитные текстовые запросы
- Длинная память диалога
- Режимы ответа (`/mode`), включая режим «База знаний»
- Генерация картинок (`🖼 Картинка`)
- Анализ фото и распознавание голоса
- Загрузка PDF (разовый вопрос по документу)
- Веб-поиск в реальном времени (`🌐 Веб-поиск`)

Администратор (`ADMIN_USERNAMES`) получает полный доступ ко всему списку без ограничений и без
покупки, плюс эксклюзивные команды `/kb_add`, `/kb_list`, `/kb_clear`, `/reward_top10`.
